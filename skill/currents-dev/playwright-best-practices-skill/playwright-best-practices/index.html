TLDR

A guide to Playwright testing in TypeScript. The SKILL.md itself is an index: what you're doing, such as writing a test, chasing a timeout, mocking an OAuth popup or splitting tests across CI machines, points to a few of 57 reference files. They cover the basics, debugging, test types, browser APIs, advanced patterns, test architecture, frameworks (React, Angular, Vue, Next.js) and CI. The references hold the substance: find elements by role or label rather than CSS, rely on assertions that retry instead of fixed waits, sort flaky tests by cause (timing, the CI environment, shared data between parallel workers, state leaking between tests) and confirm them with repeated runs, choose between page objects and fixtures, and fake dates, networks, payments or email. After writing or changing tests, the agent runs them, reads the trace when one fails, fixes it and reruns, and moves on only when everything passes.

Test Validation Loop

After writing or modifying tests:

  1. Run tests: npx playwright test --reporter=list
  2. If tests fail:
    • Review error output and trace (npx playwright show-trace)
    • Fix locators, waits, or assertions
    • Re-run tests
  3. Only proceed when all tests pass
  4. Run multiple times for critical tests: npx playwright test --repeat-each=5
