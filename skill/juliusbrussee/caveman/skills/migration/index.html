TLDR

Before editing, the agent maps the current readers, writers and data shape, how long old and new versions must coexist, and who owns each part. It defines a forward path and a rollback path, keeps existing data intact, and makes any destructive step explicit and separately authorized. If old and new versions may run at the same time during a rollout, both must keep working. It follows the expand, migrate, verify, contract order: add the new form next to the old one, move over, check, and only then remove the old. Retries must be idempotent, and partial failures visible. It verifies the old and new paths at each stage and stops at the stage you asked for: if you asked only to add the new form, removing the old one is a separate request.

name: migration
description: Implement reversible compatibility-safe transitions. Use for schema, data, API, protocol, configuration, or dependency migrations requiring rollback and preservation proof.

Migration

Map current readers, writers, data shape, compatibility window, and ownership before editing.

  • Define forward path and rollback path.
  • Preserve existing data; make destructive steps explicit and separately authorized.
  • Keep mixed-version operation safe where rollout can overlap.
  • Sequence expand, migrate, verify, then contract when applicable.
  • Make retries idempotent and partial failure observable.
  • Verify old and new paths at required transition stages.

Stop after requested stage passes; do not perform later destructive contraction implicitly.
